# Vintrace — UI Product-Love & Micro-Interaction System

> One consistent interaction-detail system across all tabs, for macOS + Windows desktop (shared React renderer). Audited per-tab; every touch composes from a shared primitive catalog so polish reads as a system, not scattered effects.

## The primitive catalog (quick reference)

- `press-settle` Pressable / active feedback: Press on any button/row/tile -> scale(.985) settle (AI-toggle .96) -> --dur-instant + --ease-decelerate; reduced-motion: transform:none.
- `hover-lift` Hover affordance: Pointer hover -> translateY(-1px) + gains --shadow/--inner-highlight, bg --control-bg->--control-bg-hover -> --dur-quick + --ease-decelerate; reduced-motion: bg/opacity only.
- `select-morph` Selection-state morph: Item becomes selected -> checkbox/ring scales in 0->1 + siblings dim, ring grows 0->2px accent -> --dur-base + --ease-spring; reduced-motion: check at full size, ring/dim cross-fade.
- `dynamic-icon` Dynamic icon (animates briefly while active): Element becomes active -> icon performs its verb once then settles (the seven navIcon* gestures) -> --dur-slow + --ease-decelerate (spring for greeting icons); reduced-motion: tint swap, no gesture.
- `save-settle` Optimistic save + settle confirmation: Optimistic write resolves OK -> success-tint flash + checkmark pop/draw + drain to rest -> --dur-moderate + --ease-spring, first use of dormant --success-control-* tokens; reduced-motion: tint cross-fade, no checkmark.
- `count-roll` Count / badge number transition: Badge value changes -> old digit slides out / new slides in + capsule scale(1->1.12->1) bump on 999px pill -> --dur-quick digit + --ease-spring bump; reduced-motion: value swaps in place.
- `reveal-stagger` List / grid reveal stagger: List commits after load -> items fade + translateY(6px->0) staggered ~24ms/item (cap 8), zero layout shift -> --dur-moderate + --ease-decelerate; reduced-motion: fade together, no translate/stagger.
- `content-crossfade` Loading -> content crossfade: Skeleton resolves -> shimmer cross-fades out as content fades + translateY(4px->0) in, optional one-shot bootGlint sheen -> --dur-moderate + --ease-decelerate; reduced-motion: skeleton hides, content opacity-fades.
- `empty-charm` Empty / first-run charm: View has no content -> low-intensity accent-gradient orb breathes/spins + copy & action chips fade-stagger ('never a gray box') -> --dur-ambient loop + --dur-moderate entrance; reduced-motion: static orb frame, copy fades once.
- `undo-strip` Undo affordance: Reversible action completes -> frosted strip slides up + fades from bottom edge with draining bootGlint-style timer bar -> --dur-moderate + --ease-decelerate; reduced-motion: fade only, bar is real progress.
- `toast-notice` Toast / notice: Result or error announced (ok/warn/error/busy) -> translate + fade in from edge, auto-dismiss fade, past-tense count-bearing copy -> --dur-moderate + --ease-decelerate; reduced-motion: opacity fade, role=alert/aria-live kept.
- `action-bar-spring` Selection action bar: Selection count crosses 0->>=1 -> bottom bulk-action bar springs up from edge translateY(100%->0) -> --dur-base + --ease-spring; reduced-motion: slide/fade up with --ease-decelerate, no overshoot.
- `detail-open` Lightbox / detail open (shared-element zoom): Tile tapped -> shared-element zoom from the tile transform-based -> --dur-slow + --ease-emphasized; reduced-motion (CSS + preload JS flag): plain opacity fade.

## Philosophy — What "Product Love" Means in Vintrace

Product love is not decoration; it is the system *narrating its own competence*. Every Vintrace interaction should answer three questions the user never has to ask aloud: *Did it hear me?* (the press settles), *Is it working?* (the surface lives), *Did it land?* (the result confirms itself). The shipped boot suite and the seven per-tab nav-icon gestures already prove the thesis — each icon **performs its verb and then settles** (`navIconScan` sweeps and zooms on the find, `navIconTwist` bites a bolt and backs off). That is the whole vocabulary in miniature: a brief, signed, *deceleration-into-rest* motion that reads as hand-authored, not generic. The job of this system is to make that one idea pervasive and identical across every tab, so nothing in the app ever swaps state silently again.

Maturity is the *accretion* of these details, not any single hero animation. A product feels mature when the hundredth small touch is as considered as the first — when the checkbox pops the same way in Library as in People, when "Saved" settles identically whether you renamed a person or merged an album. We refuse two failure modes: the *gray box* (a state with no charm — banned by the "never a gray box" mandate) and the *silent swap* (a result with no confirmation — the optimistic-save gap the substrate flagged). The discipline is **one saturated thing per viewport** and **buttery, never busy**: motion is the seasoning that signals care, and it is rationed. If a touch does not answer one of the three questions, it does not ship.

## Motion Tokens

All touches **compose from these tokens**. No ad-hoc millisecond literals, no inline `cubic-bezier()`. Adding a new interaction means *selecting* a duration and an easing from the scale below — if none fits, the scale is wrong and gets revised in review, not bypassed. The tokens are defined once in the base `:root` (`src/styles.css:1`), are theme-agnostic (durations/easings do **not** vary by light/dark), and map onto the literals already in the codebase so adoption is largely a `literal → var()` substitution.

**Easing scale** (all four already appear in shipped CSS except `--ease-emphasized`):

| Token | Value | Use |
|---|---|---|
| `--ease-decelerate` | `cubic-bezier(.22,1,.36,1)` | **House "settle" curve.** The default for anything *arriving* and *coming to rest*: entrances, hover lifts, optimistic-save settles, the nav-icon gestures. Already used ×21 — make it the default for all transitions. |
| `--ease-standard` | `cubic-bezier(.4,0,.2,1)` | Symmetric loops and pure color/opacity tweens (breathe, pulse, shimmer). Already ×12. |
| `--ease-spring` | `cubic-bezier(.34,1.56,.64,1)` | **Delight overshoot.** Reserved for the moment a thing *appears or counts*: checkbox pop, badge count-bump, selection morph, people-bob. Currently used once — promote it. |
| `--ease-emphasized` | `cubic-bezier(.2,0,0,1)` | *(new)* Strong asymmetric decelerate for large/hero transitions (lightbox open, memory open, view switch) where `--ease-decelerate` is too gentle. |

**Duration scale:**

| Token | Value | Use |
|---|---|---|
| `--dur-instant` | `90ms` | Pressed/active feedback, tooltip, instant tactile response. Fills the 0–100ms gap. |
| `--dur-quick` | `140ms` | Hover, focus ring, small fills, single count tick. Folds the 120/130/140/160 cluster. |
| `--dur-base` | `200ms` | Default UI transition: selection/hover morph, segmented-tab slide, panel state. Folds 180/200/240. |
| `--dur-moderate` | `280ms` | Card/list-item entrance (already `person-card-in` at 280ms), toast in/out, undo-strip reveal. |
| `--dur-slow` | `500ms` | Active-tab icon gestures, loading→content reveal, larger morphs. Matches navIcon `.5s`. |
| `--dur-deliberate` | `800ms` | Boot/hero staged reveals (boot text/progress already `.8s`). |
| `--dur-ambient` | `4600ms` | Idle "alive" loops (breathe/glyph already 4.6s). Long decorative loops (ring 14s, orb 9s, ken-burns 14s) stay bespoke literals — **out of the discrete scale**. |

**Composition rule.** A primitive cites at most one duration + one easing. Per-component runtime knobs stay, but **default to the scale**: e.g. `--photo-slideshow-transition-ms: var(--dur-slow)`. The `--success-control-*` color tokens already exist (`styles.css:41–43`) but have never been animated — the save-settle primitive is their first consumer.

## The Primitive Catalog

Twelve reusable primitives. Every tab **cites these by id** rather than re-authoring motion. Each specifies trigger → exact feedback (what moves, how far, which token) → on-brand visual → reduced-motion fallback. All motion is **transform/opacity only**. The master reduced-motion block (`styles.css:16170`) auto-neutralizes *any* animation via its catch-all collapse, so the fallbacks below describe the *intended residual state*, not extra code to hand-maintain (except where an explicit static frame reads better).

| id | trigger | feedback (what moves · how far · token) | on-brand visual | reduced-motion fallback |
|---|---|---|---|---|
| **press-settle** | `:active` on any button/row/tile | `transform: scale(.985)` (AI-toggle `.96`) · `--dur-instant` `--ease-decelerate`; releases back to rest | The shipped tactile press (`styles.css:13937`); transform-only, no reflow | `transform:none` (already enforced at `16191`) — instant, no scale |
| **hover-lift** | pointer hover on interactive surface | `translateY(-1px)` + gain `--shadow`,`--inner-highlight`; bg `--control-bg → --control-bg-hover` · `--dur-quick` `--ease-decelerate` | The "crafted edge" specular lip appears as the surface rises a hair; floats like chrome | opacity/bg swap only, no translate; focus-visible ring still shows |
| **select-morph** | item enters selected state (grid cell, person, photo) | checkbox/ring **scales in** `0 → 1` with `--ease-spring`; cell dims unselected siblings (opacity → .92), selection ring grows 0→2px · `--dur-base` | Spring "pop" of the round check; ring tinted `--accent` (chrome) — selection is the one saturated thing | check appears at full size, no pop; ring/dim cross-fade only |
| **dynamic-icon** | element becomes active/selected (nav tab, segmented tab, toggle) | the icon **performs its verb once, then settles**: short transform gesture · `--dur-slow` `--ease-decelerate` (spring for "greeting" icons) | The seven shipped `navIcon*` gestures (`styles.css:1037–1086`) are the canonical set; new active icons author a sibling gesture | no gesture; icon swaps to active tint instantly (gated by `no-preference` already at `1003`) |
| **save-settle** | optimistic write resolves OK (rename, merge, favorite, edit) | row/control flashes `--success-control-bg/-border/-text`, a checkmark **draws/pops** (`--ease-spring`), then drains back to rest · `--dur-moderate` | First-ever use of the dormant `--success-control-*` tokens; a `bootGlint`-style sheen may sweep the row once | success-tint cross-fade in/out, no checkmark draw, no sheen |
| **count-roll** | a badge/count value changes | old digit slides up/out, new slides in; capsule does a `scale(1→1.12→1)` **bump** · `--dur-quick` digit, `--ease-spring` bump | `999px` pill geometry, weight 700, tabular-nums; tones `.green/.amber/.blue`/`--accent` | new value swaps in place, no roll, no bump |
| **reveal-stagger** | a list/grid commits after load | items fade + `translateY(6px → 0)`, staggered ~24ms/item (cap ~8) · `--dur-moderate` `--ease-decelerate` | Mirrors shipped `person-card-in`; month headers render the instant counts arrive — **zero layout shift** | all items fade in together, no translate, no stagger |
| **content-crossfade** | skeleton → real content (loading resolves) | skeleton cross-fades out as content fades + `translateY(4px→0)` in; optional one-shot `bootGlint` sheen on first paint · `--dur-moderate` `--ease-decelerate` | Extends the canonical `skeletonShimmer`; the brand's signature glint reveal flourish | skeleton hides, content opacity-fades in; no glint, no translate |
| **empty-charm** | a view has no content (first-run or filtered-to-empty) | a low-intensity **accent-gradient orb** breathes (`scale 1↔1.03`/`orbBreathe`) + faint `orbSpin`; copy + action chips fade-stagger in · `--dur-ambient` loop, `--dur-moderate` entrance | Low-intensity reuse of the living orb / boot "Plasma Silk"; **"never a gray box."** Filtered-empty adds active-filter recap chips + "Clear filters" | orb renders one static frame (no spin/breathe), copy + chips fade in once |
| **undo-strip** | a reversible action completes (delete, move, merge) | strip **slides up + fades** from bottom edge (`translateY(8px→0)`) with a draining timer bar · in/out `--dur-moderate` `--ease-decelerate`; bar drains over its lifetime | Frosted `--glass` capsule wearing `--shadow`+`--inner-highlight`; timer bar reuses the `bootGlint`/progress idiom | fades in/out, no slide; timer bar may shrink (it's a width/progress, not decorative) — or show a static "Undo" with no bar |
| **toast-notice** | a result/error needs announcing (`ok/warn/error/busy`) | translate + fade in from edge (`translateY(8px→0)`), auto-dismiss with fade · `--dur-moderate` `--ease-decelerate` | `.notice` variants get their first entrance keyframe; frosted glass + crafted edge; copy is past-tense, count-bearing | opacity fade in/out only; `role="alert"`/`aria-live` unchanged |
| **action-bar-spring** | selection count crosses 0 → ≥1 (bulk affordance) | the bottom action bar **springs up from the edge** (`translateY(100% → 0)`) · `--dur-base` `--ease-spring`; springs back down at 0 | The "settle" of a destructive/bulk affordance per the phase-1 spec; frosted, floating chrome | slides/fades up with `--ease-decelerate`, no overshoot |

Both reduce to existing primitives and the same fallbacks.

## Sound, Notification & Badge Mapping

**There are no true haptics on desktop** — neither macOS nor Windows exposes a trackpad/Taptic API to an Electron renderer. The "haptic-equivalent" is therefore always the **visual primitive** above; an optional **system sound** and/or **OS channel** (notification, dock/taskbar badge, taskbar progress) may *accompany* it, never replace it. Every channel below requires *new* preload + main wiring (the platform substrate confirms all of these are currently absent or backend-only), and every one is **gated by platform capability AND a user setting**, defaulting conservative.

| Primitive | Visual (always) | Optional sound | OS channel | Gates |
|---|---|---|---|---|
| **save-settle** | success flash + checkmark | *none by default* (soft tick only if "Interface sounds" ON) | — | `shell.beep` is the only sound primitive; off by default; never on every keystroke-grade save |
| **toast-notice** (error) | edge slide-in, red tone | optional alert beep on `error` only | — | sound only if user enabled; calm, blameless copy unchanged |
| **toast-notice** (long-job complete) | in-app notice | optional completion sound | **native notification** *only if window unfocused* | reuse `notify()` (`main.cjs:2066`) via a **new renderer-triggerable IPC**; suppressed when focused or `CROSSAGE_DISABLE_NOTIFICATIONS`/setting off |
| **count-roll** (queue/candidate count) | pill bump | — | **dock/taskbar badge** `setQueueBadge(n)` (new) | wired only when there's a meaningful backlog; cleared at 0; respects "Show counts on app icon" setting |
| **scan/index progress** | in-window progress (shared `onScanProgress`) | — | **taskbar/dock progress** `setTaskProgress(fraction)` (new; `setProgressBar`, currently 0 hits) | fed by existing progress events; indeterminate mode on Win when unknown |
| **attention** (job done while app backgrounded) | — | optional | **dock bounce (mac) / `flashFrame` (Win)** via one `requestAttention()` verb | only when unfocused + setting on; never steals focus |

**Intent-level verbs, OS-correct in main.** The renderer's love-touch logic stays identical — it calls `notify({title,body})`, `setQueueBadge(n)`, `setTaskProgress(f)`, `requestAttention()` — and main does the platform-correct thing (dock vs taskbar overlay, bounce vs flashFrame). Copy follows the shipped voice: **past-tense, count-bearing, period-terminated** ("Saved face photos added: {count}."), British "cancelled". Any new string (undo, "caught up", first-run charm) needs **all 7 locales** or `check-localization.cjs` fails.

## Platform Consistency Rules

**Identical in the shared renderer on macOS & Windows** — *the love-touches themselves live here.* All twelve primitives are pure CSS/DOM and **must look and time-out byte-identically** on both OSes: press-settle, hover-lift, select-morph, dynamic-icon, save-settle, count-roll, reveal-stagger, content-crossfade, empty-charm, undo-strip, toast-notice, action-bar-spring. `onScanProgress` (`backend:progress`) is the shared data source — render the same in-window progress on both. `window.crossAge.platform` is the **only** branch key the renderer has; use it sparingly and only for the adaptations below.

**Adapts only where the OS demands it** (push specifics into main/preload; expose a *normalized* result so the renderer branches minimally):

- **Vibrancy / material:** macOS `setVibrancy('sidebar'/'under-window')` vs Win11 `backgroundMaterial: 'mica'/'acrylic'` — different ctor APIs. Renderer surfaces stay translucent **only when a material was actually applied**. Both **must be disabled** under reduced-transparency / forced-colors.
- **Accent color:** normalize macOS `controlAccentColor` and Windows `getAccentColor()` into the single `--accent` custom property the renderer already consumes; the *fetch* + live `nativeTheme/systemPreferences 'updated'` subscription live in main. Chrome uses `--accent` (blue); **alive moments** use `--accent-vivid` (violet→magenta) — that is what ships today and the canonical split.
- **Title bar / window controls:** mac traffic lights (`hiddenInset`, inset already positioned `main.cjs:3619`) vs Win caption buttons (would need `titleBarOverlay` color to track theme). Any renderer drag region reserves the correct side/inset per `platform`.
- **Live theme:** subscribe `nativeTheme 'updated'` in main (currently read **once** at startup) and push to the renderer so a mid-session OS theme switch is honored beyond CSS `prefers-color-scheme`.
- **Reduced-motion:** CSS `@media (prefers-reduced-motion: reduce)` already covers all CSS animation cross-OS for free. **JS-driven** motion (any rAF count-up, FLIP, shared-element zoom) must additionally check a new preload `prefersReducedMotion` getter/event (`getAnimationSettings`), since main has no JS awareness of it today.
- **Increased / high contrast:** Windows is covered by the existing `@media (forced-colors: active)` block (`styles.css:16223`). macOS `shouldUseHighContrastColors` has **no** handler — if respected, push a body class from a main theme subscription, not per-OS CSS.
- **Share confirmation:** macOS native `ShareMenu` vs Win/Linux reveal-in-folder fallback. `shell:share-paths` already returns `{supported, fallback}` — the **toast-notice** must word itself from that payload ("Shared" vs "Revealed in Explorer"), never assume success.

## Accessibility & Performance Floor

Non-negotiable for **every** primitive:

- **Reduced-motion honored automatically.** The master block (`styles.css:16170`) collapses any animation's duration + iteration via its catch-all `*:not(.spin)` rule — future primitives are neutralized **without** editing a selector list. `.spin` stays exempt so loaders never look hung. Each primitive's reduced-motion fallback above is the intended *residual* (opacity-only fade, no translate/scale/overshoot); JS-driven motion must additionally honor the preload `prefersReducedMotion` flag.
- **60fps via transform/opacity only.** Every primitive animates `transform` and/or `opacity` — **never** width/height/top/left/margin (the only width-driven motion permitted is genuine progress, e.g. the undo timer bar and `--boot-fill`). No layout thrash: reveals and morphs must not reflow neighbors (the nav-icon gestures are explicitly contained to the icon's grid cell). Skeletons are row-shaped to the real layout for **zero layout shift** on content-crossfade.
- **Visible keyboard focus, always.** `:focus-visible` rings are never suppressed by hover/selection state; under `forced-colors` the system `Highlight` outline restores (`styles.css:16238`). Focus order, `aria-current`, and `aria-label="Primary navigation"` are preserved through every animated state change.
- **Announce, don't just animate.** toast-notice/error keep `role="alert"` + `aria-live` (`assertive` for errors); count-roll and save-settle update accessible text/`aria-label` at the value change, so non-visual users get the result the animation is celebrating.
- **Rationed, not constant.** Ambient loops (empty-charm orb, breathe) run at low intensity and pause where possible; "one saturated thing per viewport." Motion that does not answer *heard / working / landed* does not ship.

**Verification notes / drift fixes:** Every touch maps to a real catalog primitive — no invented `new:` IDs. Two reframings vs. the draft for honesty: (1) the undo touch is an **upgrade of the existing `.photo-operation-undo` element**, not a from-scratch surface, so its effort drops L→M and it stops claiming the silent-`setMetadataError`-only state; (2) the skeleton and empty-state touches both **reuse keyframes that already ship** (`skeletonShimmer`, `orbSpin`/`orbBreathe`), which is what keeps them feasible and on-vocabulary. Nothing here is decorative noise that fights "buttery, not busy" — the staggers are capped, the count-roll preserves tabular width, and the density settle is constrained to transform/opacity so the virtual grid's measured bands stay authoritative.

**Signature moment:** the **Favorite optimistic pop + success-tint settle** (`save-settle`). It is the first real use of the dormant `--success-control-*` tokens on the grid, it turns the single most-repeated gesture in a Photos app from a flat next-render badge into an honest, tactile "saved" — and making `setItems` optimistic is the small correctness fix that earns the delight. It is the touch that most reads as "product maturity accreting over time."

**Open questions:**
- **No shared toast/notice host exists.** Results surface through scattered local `aria-live`/`role="alert"` elements (`.photo-consolidation-result`, `.photo-load-error`, `.photo-global-search-status`). Any future `toast-notice` work — and a clean home for non-undoable bulk results — needs a shared `new:toast-host` primitive across all tabs; the undo-strip here dodges this only because it reuses the existing undo element.
- **The `--dur-*` / `--ease-*` motion tokens are NOT defined yet** (confirmed: `--shadow`, `--inner-highlight`, `--control-bg-hover`, `--success-control-*` exist; no duration/easing custom properties anywhere in styles.css — motion currently uses inline cubic-beziers like the 180ms tile transition). ## Rollout phasing

Waves group **all** touches across all seven tabs. A wave ships only after its shared prerequisite lands, so the catalog vocabulary is real before any consumer references it.

**Wave 0 — Shared substrate (blocks everything; not user-visible alone).**
Rationale: every touch references `--dur-*`/`--ease-*` tokens and `--success-control-*`, but only the success tokens and the keyframes (`orbSpin`/`orbBreathe`/`skeletonShimmer`/`bootGlint`/`navIcon*`) exist — no duration/easing custom properties exist anywhere in styles.css. Ship: (a) the `:root` motion-token block (one-time, cross-tab); (b) one authored reusable `save-settle` gesture (net-new to the whole app — no checkmark/success-tint settle exists yet); (c) the **shared `toast-host` primitive** (the one genuinely new primitive, confined to open questions until now) so `toast-notice` stops forking per-tab `aria-live` one-offs; (d) the JS `prefersReducedMotion` preload getter/event. Until 0 lands, every wave below would re-hard-code inline cubic-beziers (the codebase's current `cubic-bezier(0.22,1,0.36,1)` habit) — that *is* the drift we are paid to prevent.

**Wave P0 — The confirmation backbone (the "it did the thing" beats).**
Rationale: turn the single most-repeated, currently-silent action on each tab into a felt confirmation, plus the load→content handoff so nothing pops. Purely renderer-local; no OS amplifiers required.
- `save-settle`: Library favorite pop, Memories favorite/save, Albums "album saved" (signature), People&Pets Accept/Reject (signature, on the **outgoing** row), Tools model-download "Ready" (signature), Settings Save flash+checkmark (signature).
- `reveal-stagger` + `content-crossfade` as a pair: Library grid (skeleton reuses `skeletonShimmer` 13927), Memories For-You, Albums folders-then-albums, Search ranked results+skeleton, People&Pets roster reveal, Tools panels.
- `dynamic-icon` on the signature control where it's the cheapest win: Search Sparkles `navIconTwinkle` on AI engage (signature, S), People&Pets decision-icon verb, Settings sub-nav verbs.
- `count-roll` only where it's already gated/cheap: Tools live scan counters (keyed to the **flushed** rAF value, skip 0→0), Library selected-count, Settings dirty-count→0.
- `action-bar-spring`: Library + People&Pets bulk bars (both already-mounted, just spring them).

**Wave P1 — Texture, charm, and reversibility.**
Rationale: the surfaces are confirmed; now make them *alive* and *safe*. Brings in the "never a gray box" rule and the safety nets, plus the OS amplifiers (tier 3–4 wiring) where they help.
- `empty-charm` everywhere (orb reuse `orbSpin`/`orbBreathe`): Library, Memories, Albums, Search seeds, People&Pets (both empties), Tools (3 diagnostics panels).
- `undo-strip`: Memories Feature-less (signature — the regret→trust moment), Albums remove/delete, Settings Reset-defaults (NOT irreversible delete), People&Pets decision undo (restyle the static `.undo-strip`), Library `.photo-operation-undo` restyle.
- `toast-notice` (now that `toast-host` exists): Memories export/reset, Albums results, Search result/error, Settings data-ops; background mirrors via the new `notify()` IPC where appropriate.
- `select-morph` (real selection): Library tiles, People&Pets review rows + lane buttons, Settings preset cards + sliding sub-nav pill, Search suggestion chips.
- `hover-lift`/`press-settle` fill-in on the conspicuously-flat controls: Memories strip cards, Tools ETA/priority rows, Settings data-ops column.
- `count-roll` texture pass: dashboard metrics, model-% pill, membership counts, confidence chips, storage over-budget.
- OS amplifiers: `setTaskProgress` for the Tools scan/model bars, `setQueueBadge` for queue/candidate counts, accent/live-theme subscription so every P0/P1 tint reads correct on both OSes.

**Wave P2 — Signature flourishes and the risky bridge.**
Rationale: the highest-effort, highest-risk, or most-decorative touches — ship last so they sit on a proven base and can be cut without holding up the backbone.
- `detail-open` shared-element zoom: Library tile→lightbox, Memories cover→slideshow (the lone L-effort item; needs the FLIP measurement bridge across `pendingMemoryPlayId` and the JS reduced-motion flag from Wave 0). Memories Touch #8 disc-verb `dynamic-icon` ships as its **reduced-risk on-ramp** and must sequence *into* the zoom, never fire as a competing second motion.
- `save-settle` (tint-only) Albums drag-reorder landing; Tools queue-add/capture settles.
- Remaining `dynamic-icon` polish (Library date-view segment, Albums kind badge, Tools job icon), Settings Safe-Mode pulse (P3-flavored, scoped to the one safety-critical toggle).
- Density/aspect settle, scope-hint roll, clear-button crossfade — the buttery-edge touches kept small and last.

**How we'll know it worked.** Three perceived-quality signals, checked per tab on both OSes:
1. **Confirmation latency feels instant.** Because `save-settle` rides optimistic writes (e.g. Library `setItems` moved *before* the await, People&Pets `decide()` already optimistic), the settle plays on the user's action, not the network round-trip. Success reads as "already done, just confirming" — never a spinner-then-result.
2. **No flash-of-unstyled / no pop.** Skeleton→content is always a `content-crossfade` handoff into a `reveal-stagger` entrance with **zero layout shift** (bands/aspect-ratios reserve geometry first); the `skeletonShimmer` class finally has a rule (it currently renders nothing); empty views are an `empty-charm` orb, never the dashed/gray box the brand rejects. Visually: no bare glyph hard-swapping to a photo, no dashed box, no counter snapping.
3. **Reduced-motion parity is total.** Every primitive has a defined reduced-motion degrade (ring/dim cross-fade, value-swaps-in-place, tint-without-checkmark, static orb frame, fade-without-stagger, real-progress timer bars), all driven by the one shared `prefers-reduced-motion` system — so a reduced-motion user gets the *same information and confirmation*, just without travel. The JS-driven touches (`detail-open`, scan count-rolls) honor the new preload `prefersReducedMotion` flag, so nothing animates in JS that CSS was told to suppress. If a reduced-motion pass ever shows a missing confirmation or a residual zoom, that is the regression signal.
