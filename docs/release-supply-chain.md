# Release Supply-Chain Evidence

Vintrace release workflows produce interoperable dependency, integrity, provenance, and signing evidence for every top-level installer, updater companion, update manifest, and MCPB artifact.

The macOS, Windows, and Linux workflows are reusable native build authorities. They verify their own package and upload caller-scoped Actions artifacts, but they cannot create or mutate a GitHub Release. `.github/workflows/release.yml` is the sole release publisher.

## Evidence set

Each release build emits:

- `SHA256SUMS.txt`: the canonical, strict SHA-256 subject list.
- `vintrace.cdx.json`: CycloneDX 1.6 JSON generated by Syft 1.44.0.
- `vintrace.spdx.json`: SPDX 2.3 JSON generated by the same Syft invocation.
- `vintrace-build-metadata.json`: unsigned-at-creation diagnostic build context. This file explicitly does not claim to be provenance; it becomes a signed subject with the rest of the release.
- `vintrace-slsa-provenance.attestation.sigstore.json`: GitHub-hosted SLSA provenance for every checksum subject.
- `vintrace-cyclonedx.attestation.sigstore.json`: the exact CycloneDX document bound to every checksum subject.
- `vintrace-spdx.attestation.sigstore.json`: the exact SPDX document bound to every checksum subject.
- `<subject>.sigstore.json`: a cosign keyless blob-signing bundle for every checksum subject and for `SHA256SUMS.txt` itself.
- `SHA256SUMS.txt.sig`, when an Ed25519 updater key is configured. This remains the compact origin proof consumed by the in-app updater; it is separate from Sigstore verification.

The SBOM scan is deliberately limited to `package.json`, `package-lock.json`, and `requirements-production.lock.txt`. It includes Electron even though Electron is a development dependency in npm metadata because Electron is the shipped application runtime. It never scans local virtualenvs, user workspaces, previews, model caches, build output, or filesystem paths.

Every GitHub Action in `.github/workflows` is pinned to a full commit SHA. Version comments remain beside the pins for maintenance readability.

## Release gate

The cross-platform release uses this order:

1. Require a manual dispatch on `refs/tags/v<package version>`, bind that tag to `GITHUB_SHA`, serialize runs for the ref, and refuse an existing published or populated draft release.
2. Run the reusable macOS, Windows, and Linux build workflows in parallel. Each verifies native signing where applicable, its frozen app/backend, local checksum/SBOM/attestation set, and package acceptance before uploading an Actions artifact.
3. Download all three artifacts into isolated directories. `release:assemble` re-verifies exact checksum and build-metadata inventories, commit/ref/repository identity, SBOM records, required payload cardinality, and regular-file shape; it rejects symlinks, unexpected files, missing evidence, and case-insensitive filename collisions, then copies payload bytes only.
4. Re-run cosign and GitHub attestation verification over each transferred platform artifact against its reusable-workflow identity, exact source commit/ref, issuer, and hosted-runner policy.
5. Generate one aggregate `SHA256SUMS.txt`, CycloneDX document, SPDX document, and build record over the complete cross-platform payload. The build record embeds a schema-validated three-platform assembly manifest whose names and hashes must exactly equal the aggregate payload inventory.
6. Generate GitHub SLSA and exact-SBOM attestations, keylessly sign every aggregate subject, and immediately verify workflow/ref/commit/issuer/hosted-runner identity.
7. Prepare and live-validate the dual-platform MCP Registry descriptor before staging any release.
8. Fetch the remote tag again and require that it still resolves to `GITHUB_SHA`; then stage the complete release once with overwriting disabled, download every aggregate subject/evidence bundle through the authenticated draft API, and run `release:verify --platform all`.
9. Publish once, repeat the all-platform verification through public URLs, then authenticate the official MCP publisher with GitHub OIDC and publish the immutable descriptor.

Independent platform publication was deliberately removed. It could overwrite identically named checksum/SBOM/attestation assets and could expose a partial release before peer platforms finished.

Protect release tags against force-pushes with repository rules. The workflow detects a tag that moves before staging, but repository policy is still required to prevent later retargeting of a published tag.

The resulting provenance satisfies the SLSA Build level 2 hosted-build and signed-provenance requirements only after a real GitHub-hosted run succeeds. A local `npm run release:artifacts` result is not SLSA provenance.

## Verify a release

Download the release payload, `SHA256SUMS.txt`, all three attestation bundles, and the matching `<subject>.sigstore.json` bundle into one directory.

Verify checksums:

```bash
shasum -a 256 -c SHA256SUMS.txt
```

Verify a keyless blob signature. Replace the workflow ref with the ref recorded by the release build:

```bash
cosign verify-blob \
  --bundle "Vintrace-0.1.0.dmg.sigstore.json" \
  --certificate-identity "https://github.com/harsh2929/crossage-fr-workbench/.github/workflows/release.yml@refs/tags/v0.1.0" \
  --certificate-oidc-issuer "https://token.actions.githubusercontent.com" \
  "Vintrace-0.1.0.dmg"
```

Verify SLSA provenance with GitHub CLI. Use `vintrace-build-metadata.json` for the source commit and ref recorded by that build:

```bash
gh attestation verify "Vintrace-0.1.0.dmg" \
  --bundle vintrace-slsa-provenance.attestation.sigstore.json \
  --repo harsh2929/crossage-fr-workbench \
  --signer-workflow harsh2929/crossage-fr-workbench/.github/workflows/release.yml \
  --source-digest <40-character-source-commit> \
  --source-ref <refs/tags/v0.1.0> \
  --deny-self-hosted-runners
```

For the SBOM attestations, add the corresponding predicate:

```bash
gh attestation verify "Vintrace-0.1.0.dmg" \
  --bundle vintrace-cyclonedx.attestation.sigstore.json \
  --repo harsh2929/crossage-fr-workbench \
  --signer-workflow harsh2929/crossage-fr-workbench/.github/workflows/release.yml \
  --predicate-type https://cyclonedx.org/bom \
  --deny-self-hosted-runners

gh attestation verify "Vintrace-0.1.0.dmg" \
  --bundle vintrace-spdx.attestation.sigstore.json \
  --repo harsh2929/crossage-fr-workbench \
  --signer-workflow harsh2929/crossage-fr-workbench/.github/workflows/release.yml \
  --predicate-type https://spdx.dev/Document/v2.3 \
  --deny-self-hosted-runners
```

Every public release payload uses `.github/workflows/release.yml` as the aggregate signer workflow. The reusable platform workflows retain separate caller-run evidence proving their native build gates, but those intermediate bundles are not uploaded under colliding public release names.

## Trust boundary

Sigstore evidence complements, rather than replaces, Apple Developer ID/notarization, Azure Authenticode/timestamping, and the Ed25519 updater manifest. SBOM presence does not establish that dependencies are vulnerability-free, and provenance does not make a compromised source commit trustworthy. It proves which hosted workflow built the named bytes from the recorded source revision and makes substitution detectable.

The workflows fail closed if the GitHub attestation API, OIDC signing service, Registry validation service, or public post-publication download verification is unavailable.
